# deck-viz — インフォグラフィックの生成とレビュー

## この skill が要る理由

Codex は 1 枚のスライドを 2〜3 分で作る。だが**自分の出力を人間の目で見ていない**ので、
日本語の改行崩れ・文字化け・重複表示・宙に浮いた線といった「見れば一発で分かる粗」を残す。
一方こちらは PNG を見て判断できる。**Codex が手を動かし、こちらが目になる**——これが基本の分業。

速く収束させる鍵は、指摘の「具体さ」と「範囲の狭さ」の 2 つに尽きる。

## 全体像

```
make_prompts.py   ← 文言の正本。ヘッドライン・素材はここだけを直す
      ↓ uv run python make_prompts.py
prompts/*.md      ← 生成物。手で編集しない
      ↓ ./gen.sh <stem> ["指摘"]
out/<stem>.png    ← 成果物（1920×1080）
```

恒久ルールは 2 つのファイルにある。**Codex は毎回この 2 つを読む。**

- `deck-viz/AGENTS.md` — 役割・出力規約・文体・用語の言い換え
- `deck-viz/STYLE.md` — 配色・文字サイズの下限・日本語組版・線の作法・出力チェック

## 進め方

### 1. 文言を変えるなら make_prompts.py

ヘッドラインや素材の文を変えるときは `make_prompts.py` の `SLIDES` を直し、
`uv run python make_prompts.py` で `prompts/` を作り直す。`prompts/*.md` を手で直すと次回上書きされる。

素材は**カードに載る短句**として書く。長い文を渡すと、Codex は狭いボックスに流し込んで改行を壊す。
「実在する一人の記録を、そのまま出力に入れません」より「実在する記録は出力に入れません」。

### 2. 生成する

```bash
cd deck-viz
./gen.sh 05-min          # 1 枚
./gen.sh                 # 14 枚
```

**7 枚ずつのバッチに割って、バックグラウンドで回す。** 1 枚 2〜3 分なので 7 枚で 20 分前後。
バッチの完了を待つ間に、前のバッチの PNG をレビューできる。これで実時間がほぼ半分になる。

**同じディレクトリで codex を並行させない。** 一時ファイルが衝突する。
バッチ A の完了を待ってからバッチ B を始めること。

### 3. PNG を 1 枚ずつ見る

Read で PNG を開く。**すべて開く。** サムネイルや推測で済ませない。粗は必ず画像側にある。

見る順は `references/review-checklist.md` に置いた。特に見落としやすいのは、
**改行の崩れ**（助詞 1 文字の行）と**中身の無い枠**（豆腐に見える）と**同じ文言の二重表示**。

### 4. 指摘を書いて再依頼する

```bash
./gen.sh 09-no-records '- 「その傾向から架空の人物を作りま／す」と送り仮名の途中で折れている。文節で折る。
- それ以外は良いので、大きく変えないこと。'
```

**指摘の書き方が結果を決める。** 効いた書き方と効かなかった書き方は
`references/feedback-patterns.md` にまとめてある。要点だけ先に:

- **画面に出ている文字列をそのまま引用する。** 「改行がおかしい」では直らない。
  「全チー／ムに公開 と 3 行に割れている」なら直る。
- **必ず「それ以外は良いので、大きく変えないこと」で締める。** これが無いと Codex は
  構図ごと作り直し、前の巡で直った点まで壊す（実際に 05 の合流図が一度失われた）。
- **1 枚あたり 3〜5 点まで。** 多いと全部作り直される。

### 5. 3 巡で打ち切る

実測では、第 1 巡で大枠、第 2 巡で不具合の大半、第 3 巡で仕上げ、という収束をした。
4 巡目以降は改善と劣化が入れ替わるだけになりやすい。3 巡で残った粗は、
指摘の書き方が悪いか、そもそも素材が図に向いていない。**プロンプト側を疑うほうが早い。**

## 恒久ルールと個別指摘の切り分け

ここを間違えると同じ指摘を 14 回書くはめになる。

| 種類 | 置き場所 | 例 |
|---|---|---|
| 全スライドに効く | `STYLE.md` / `AGENTS.md` | 文字サイズの下限、日本語の折り方、線の作法、用語の言い換え |
| そのスライドだけ | `./gen.sh` の第 2 引数 | 「min の合流が横一列になっている」「24 人のラベルが点群に重なる」 |

**2 枚以上で同じ粗が出たら、それは恒久ルールの穴。** 個別指摘で潰さず `STYLE.md` に書く。
今回は「要素間に空白を出さない実装にする」「カードの高さは中身に合わせる」がこれに当たった。

なお `gen.sh` の `BASE`（毎回添える念押し）は**実測で守られなかった項目だけ**を置く場所。
`STYLE.md` の丸写しにすると効きが薄れる。

## つまずきどころ

- **`gen.sh` の PNG 確認が空振りすることがある。** codex 終了直後にファイルが見えない。
  スクリプト側で待つようにしてあるが、「失敗」と出ても `ls out/` を確認する。
- **Codex は `STYLE.md` に追記してくることがある**（「05-min で確立した図の語彙」など）。
  内容が妥当なら残してよい。プロンプトで「STYLE.md は変更しない」と書いた枚では触らない。
- **数値は `make_prompts.py` の `facts` に列挙したものが「必ず正確に載せる数値」として渡る。**
  素材から数値を消したら `facts` からも消す。載らない数値を要求すると Codex が迷う。

- `references/feedback-patterns.md` — 効いた指摘・効かなかった指摘の実例
