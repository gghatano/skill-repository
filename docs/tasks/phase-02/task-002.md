# Task 002: 集めたスキルを目的別プラグインとして配布し、価値起点で見せる

## 背景

Task 001 で、所有リポジトリに分散した `SKILL.md` を横断カタログに集約する仕組みができた。
一方で、集めたスキルを他プロジェクトで**使う**には、利用者が一覧から必要なものを選び、手で
コピーし、パスを読み替える必要があった。またカタログは「どんなスキルがあるか」を出典順・
カテゴリ順に並べるだけで、「それを使うと何が得られるか」は読み取れなかった。

同じスキルが複数リポジトリに重複していることも `docs/skill-duplication.md` で可視化された
（Task 001 のスコープ外だった重複統合が、実際の課題として浮上した）。

## 提供価値

- 利用者が、必要なスキル群を `/plugin` の 2 コマンドでどのリポジトリにも引き込める
- 利用者が、導入前に「何を入力すると何が得られるか」と「最短の始め方」を把握できる
- 重複していたスキルが役割ベースに汎化され、規約・サブエージェントごと自己完結で配布される
- 保守者が、人手で書く意味づけ（分類・要約）と機械的な収集を分離して保守できる

## スコープ

- 目的別プラグインへの再編（`plugins/<name>/`）と、マーケットプレイス `.claude-plugin/marketplace.json` の提供
- スキル本体の役割ベース汎化と、規約（`docs/`）・サブエージェント（`agents/`）の同梱
- 目的タクソノミー `catalog/categories.json` によるカテゴリ分類と、目的別カタログの生成
- 一覧ページ（`docs/index.html`）から詳細ページへ辿れる 2 層構成
  - スキル詳細ページ `docs/skills/<name>.html`（できること・使いどころ・入出力）
  - プラグイン詳細ページ `docs/plugins/<name>.html`（入力→処理→出力・かんたんな使い方・
    含まれるスキル・実行手順の例・同梱物・導入後の調整）
- 詳細ページ用の人手管理データ `catalog/skill-details.json` / `catalog/plugin-details.json`
- 人手管理データの検証（不在は許容、エントリ欠落は警告、破損は中断）
- 取りまとめの手順と考え方をまとめた `docs/aggregation-methodology.md`

## スコープ外

- 出典リポジトリへのスキルの逆同期（Task 001 から継続）
- スキル本文の自動編集・自動品質評価（プラグインへの汎化は人手で行う）
- プラグインの自動生成（どのスキルをどのプラグインに入れるかは人が決める）
- 詳細ページ用要約の自動生成（`*-details.json` は人手で書く）

## 成功条件

- `/plugin marketplace add` と `/plugin install` の 2 コマンドで各プラグインを導入できる
- 導入したスキルを `/<plugin>:<skill>` の名前空間付きで呼び出せる
- プラグイン詳細ページで、入力→処理→出力、次いで最短の始め方（コマンド 1 つ）が先に読める
- 詳細ページに記載したコマンドが実在するスキルを指している
- 人手データが壊れているときは、中身の抜けたページを配布せず同期が中断する
- 人手データにエントリが無い対象は、警告で名指しされる（黙って劣化しない）
- 実テンプレート・実データを読むスモークテストが、GitHub 認証なしで通る
- 同期元と人手データに変更がなければ tracked file に差分が生じない

## 運用

Task 001 と同じく週次 Actions が同期 PR を作成する。`main` 更新時に `deploy-pages.yml` が
`docs/` を GitHub Pages へ配信する。

プラグインを追加・変更したときは、次を併せて更新する。

- `.claude-plugin/marketplace.json`（掲載）
- `catalog/plugin-details.json`（入力→処理→出力・使い方・実行手順の例）
- `catalog/categories.json`（新しいスキル名の分類。未分類は同期時に警告）

テンプレートのクラスを変更したときだけ `./web/build-css.sh` で `docs/tailwind.css` を再生成する。
