# codex-imagegen — Codex で画像を生成し Claude が目でレビューする

## この skill が要る理由

Codex は 1 枚の画像を 2〜3 分で作る。だが**自分の出力を人間の目で見ていない**ので、
日本語の改行崩れ・文字化け・重複表示・宙に浮いた線といった「見れば一発で分かる粗」を残す。
一方こちらは PNG を見て判断できる。**Codex が手を動かし、こちらが目になる**——これが基本の分業。
仕上がった PNG は最後に Claude Code 側で成果物（デッキ・ドキュメント・Artifact 等）へ取り込む。

速く収束させる鍵は、指摘の「具体さ」と「範囲の狭さ」の 2 つに尽きる。

## 全体像

```
make_prompts.py   ← 文言の正本。ヘッドライン・素材はここだけを直す
      ↓ uv run python make_prompts.py
prompts/*.md      ← 生成物。手で編集しない
      ↓ ./gen.sh <stem> ["指摘"]
out/<stem>.png    ← 成果物（1920×1080）
      ↓ preview.html で一覧レビュー → Claude Code 側で取り込み
```

恒久ルールは 2 つのファイルにある。**Codex は毎回この 2 つを読む。**

- `AGENTS.md` — 役割・出力規約・文体・見た目の語彙（Codex は cwd の AGENTS.md を自動で読む）
- `STYLE.md` — 配色・文字サイズの下限・日本語組版・線の作法・出力チェック

## 0. 作業ディレクトリを scaffold する（最初の 1 回）

このプラグインは**テンプレート一式**を同梱している。作りたい画像のための作業ディレクトリを
1 つ用意し、そこにコピーして中身を埋める。

```bash
mkdir -p viz/prompts viz/out
cp <plugin>/scripts/gen.sh <plugin>/scripts/make_prompts.py viz/
cp <plugin>/templates/AGENTS.md <plugin>/templates/STYLE.md <plugin>/templates/preview.html viz/
cp <plugin>/templates/reference.png viz/            # 差し替え用のサンプル手本画像
chmod +x viz/gen.sh
```

`<plugin>` はこのプラグインの導入先ルート（`/plugin` 導入時はプラグインの実体パス）。
そのうえで:

- `AGENTS.md` / `STYLE.md` の `＜…＞` を埋める。**配色とタイポグラフィだけがプロジェクト固有**で、
  日本語組版・文字化け対策・レイアウト作法・出力チェックはそのまま使える。
- **手本にしたい 1 枚を `viz/reference.png` に置く。** Codex はこれに寄せて作る。
  同梱の `templates/reference.png` は design vocabulary（白地・角丸カード・細い線・強調 1 箇所）を示す
  **サンプル**なので、自分の狙う見た目の 1 枚に差し替える。作り方の実例は `templates/reference.src.html`
  にある（HTML/CSS をヘッドレスで撮る＝この skill が推す方式そのもの）。
- `make_prompts.py` の `AUDIENCE` / `HOUSE_STYLE` / `SLIDES` を自分の題材にする。

## 1. 文言を作る／変えるなら make_prompts.py

ヘッドラインや素材の文は `make_prompts.py` の `SLIDES` を直し、
`uv run python make_prompts.py` で `prompts/` を作り直す。`prompts/*.md` を手で直すと次回上書きされる。

素材は**カードに載る短句**として書く。長い文を渡すと、Codex は狭いボックスに流し込んで改行を壊す。
各要素（stem / label / headline / key / structure / emphasis / blocks / facts）の意味は
`make_prompts.py` の冒頭コメントにある。**レイアウトは指定せず、エッセンスと数値だけを渡して
図解は Codex に委ねる**のが方針。

## 2. 生成する

```bash
cd viz
./gen.sh 01-overview     # 1 枚
./gen.sh                 # prompts/ 全部
```

**枚数が多いならバッチに割って、バックグラウンドで回す。** 1 枚 2〜3 分。
バッチの完了を待つ間に、前のバッチの PNG をレビューできる。これで実時間がほぼ半分になる。

**同じディレクトリで codex を並行させない。** 一時ファイルが衝突する。
バッチ A の完了を待ってからバッチ B を始めること。主役の 1〜2 枚を先に確定してから
残りを回すと、図の語彙・配色が揃いやすい（`./gen.sh 05-key 11-proof` のように先頭に渡す）。

## 3. PNG を 1 枚ずつ見る

Read で PNG を開く。**すべて開く。** サムネイルや推測で済ませない。粗は必ず画像側にある。

見る順は `references/review-checklist.md` に置いた。特に見落としやすいのは、
**改行の崩れ**（助詞 1 文字の行）と**中身の無い枠**（豆腐に見える）と**同じ文言の二重表示**。

## 4. 指摘を書いて再依頼する

```bash
./gen.sh 09-detail '- 「架空の人物を作りま／す」と送り仮名の途中で折れている。文節で折る。
- それ以外は良いので、大きく変えないこと。'
```

**指摘の書き方が結果を決める。** 効いた書き方と効かなかった書き方は
`references/feedback-patterns.md` にまとめてある。要点だけ先に:

- **画面に出ている文字列をそのまま引用する。** 「改行がおかしい」では直らない。
  「全チー／ムに公開 と 3 行に割れている」なら直る。
- **必ず「それ以外は良いので、大きく変えないこと」で締める。** これが無いと Codex は
  構図ごと作り直し、前の巡で直った点まで壊す。
- **1 枚あたり 3〜5 点まで。** 多いと全部作り直される。
- **「増やせ」と「変えるな」を同じ依頼に入れない。** 増量指示はレイアウトの再設計を必ず誘発する。

## 5. 3 巡で打ち切る

実測では、第 1 巡で大枠、第 2 巡で不具合の大半、第 3 巡で仕上げ、という収束をする。
4 巡目以降は改善と劣化が入れ替わるだけになりやすい。3 巡で残った粗は、
指摘の書き方が悪いか、そもそも素材が図に向いていない。**プロンプト側（`make_prompts.py` の
`structure` / `emphasis`）を疑うほうが早い。**

## 6. Claude Code 側で取り込む

そろった PNG を成果物へ取り込む。用途に応じて Claude に依頼する:

- **デッキ／Artifact** — 各スライドの本文を `<img>`（PNG の dataURI 等）に差し替える。
  PNG はテーマに追従しないので、埋め込むときデッキはライト固定にする。
- **ドキュメント（Markdown/HTML/PDF）** — 図として挿入する。
- **画像そのもの** — `out/*.png` が最終成果物。

## 恒久ルールと個別指摘の切り分け

ここを間違えると同じ指摘を何度も書くはめになる。

| 種類 | 置き場所 | 例 |
|---|---|---|
| 全画像に効く | `STYLE.md` / `AGENTS.md` | 文字サイズの下限、日本語の折り方、線の作法、用語の言い換え |
| その 1 枚だけ | `./gen.sh` の第 2 引数 | 「min の合流が横一列になっている」「点群にラベルが重なる」 |

**2 枚以上で同じ粗が出たら、それは恒久ルールの穴。** 個別指摘で潰さず `STYLE.md` に書く。

なお `gen.sh` の `BASE`（毎回添える念押し）は**実測で守られなかった項目だけ**を置く場所。
`STYLE.md` の丸写しにすると効きが薄れる。配色などプロジェクト固有のルールは `BASE` に書かず
`STYLE.md` に置く。

## つまずきどころ

- **Codex の非対話サブコマンド・自動承認フラグはバージョンで違う。** `codex exec --help` で確認し、
  `gen.sh` の `CODEX` / `CODEX_FLAGS` で上書きする。
- **`gen.sh` の PNG 確認が空振りすることがある。** codex 終了直後にファイルが見えない。
  スクリプト側で待つようにしてあるが、「失敗」と出ても `ls out/` を確認する。
- **数値は `make_prompts.py` の `facts` に列挙したものが「必ず正確に載せる数値」として渡る。**
  素材から数値を消したら `facts` からも消す。載らない数値を要求すると Codex が迷う。

- `references/feedback-patterns.md` — 効いた指摘・効かなかった指摘の型
