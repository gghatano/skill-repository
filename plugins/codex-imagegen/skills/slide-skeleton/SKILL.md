# slide-skeleton — スライド骨子を整える（生成パイプラインの入口）

Codex に画像を作らせる前に、**各画像の「骨子」** を固める。骨子は「何を伝えるか」だけを持ち、
レイアウト・配色・作図の実相は持たない（それは STYLE.md と Codex に委ねる）。ここを丁寧にやるほど、
後段の生成が速く収束する。

このプラグインの流れ:

```
slide-skeleton（骨子）→ prompt-build（生成用構造へ変換）→ generate-review（生成・レビュー）
      outline.md                    prompts/*.md                    out/*.png
```

## この skill の主目的: 必要な情報を揃える（intake）

骨子づくりは**穴埋めではなく聞き取り**。着手したら、下の一覧のうち**まだ分かっていない項目**を洗い出し、
ユーザーに揃えてもらう。

- **必須項目は必ず聞く。** 欠けたまま次工程（prompt-build）へ進めない。
- **推奨項目は「あると何が良くなるか」を添えて追加を促す。** ユーザーが不要と言えば無理に足さない。
- **勝手に創作して埋めない。** とくに headline の主張・`facts` の数値・固有名詞・専門用語の言い換えは、
  ユーザーの言葉を確認してから入れる。推測で埋めるとレビューで剥がれ、やり直しになる。
- **聞き方**: 不足が多ければ `AskUserQuestion` でまとめて尋ねる／自由記述を促す。少なければ会話で 1 つずつ。
  ユーザーが既に渡した情報は再度聞かない。集めた内容は `outline.md` に落とし、`＜…＞` を残さない。

### プロジェクト単位（最初に 1 回）

| 情報 | 区分 | 無いと / あると |
|---|---|---|
| 目的と作る枚数（デッキ像） | **必須** | 何を作るかが決まらない |
| audience（想定読者） | **必須** | 文体・専門用語の扱いの基準が決まらない |
| reference.png（手本画像） | **必須** | 見た目の基準。同梱サンプルのままだと自分のデッキに見えない |
| 配色・書体（STYLE.md） | **必須** | 埋めないと生成がばらつく。※ reference.png から色を拾って**提案してよい**（要確認） |
| house-style（文体規約） | 推奨 | 敬体/常体・禁止する語調・専門用語の言い換え表。文体ブレと専門用語の露出を防ぐ |

### 画像 1 枚ごと

| 情報 | 区分 | 無いと / あると |
|---|---|---|
| headline（結論の完全文） | **必須** | 図の核＝主タイトルが決まらない |
| key（最重要 1 点） | **必須** | 1 枚 1 メッセージにならない |
| material（素材の短句） | **必須** | 図に載る中身が無い |
| facts（正確に載せる数値） | 推奨 | 数値の正確さを担保できる。**数値を扱う図では実質必須** |
| structure（希望する図の構造） | 推奨 | 図の型が決まり収束が速い。無ければこちらで型を提案してよい |
| emphasis（視覚的に強調したい点） | 推奨 | 強調（色 1 箇所）の置き場所が定まる |
| label（キッカー） | 推奨 | 上に添える文脈ラベル |

### 推奨情報の促し方（例）

- 「数値を載せるなら `facts` に入れると一字も変えずに出せます。正確に載せたい数値はありますか？」
- 「図の型（比較／集約／時間軸／対立など）の希望はありますか。無ければ素材から提案します。」
- 「専門用語の言い換え（例: 会員推定攻撃 → 含まれていたかを当てる攻撃）を決めておくと、図に難語が出ません。」

必須が揃い、推奨も一通り促し終えたら、`outline.md` を書き上げて次工程へ渡す。

## 0. 作業ディレクトリを scaffold する（最初の 1 回）

このプラグインはテンプレート一式を同梱している。作業ディレクトリを 1 つ用意してコピーする。

```bash
mkdir -p viz/prompts viz/out
cp <plugin>/scripts/gen.sh viz/ && chmod +x viz/gen.sh
cp <plugin>/templates/AGENTS.md <plugin>/templates/STYLE.md <plugin>/templates/preview.html viz/
cp <plugin>/templates/outline.md <plugin>/templates/prompt.md viz/
cp <plugin>/templates/reference.png viz/     # 差し替え用のサンプル手本画像
```

`<plugin>` はこのプラグインの導入先ルート。intake で集めた情報を使って:

- `AGENTS.md` / `STYLE.md` の `＜…＞`（配色・書体）を埋める。手本画像があるなら**その色を拾って提案**し、
  確認を取ってから STYLE.md に書く。
- **手本にしたい 1 枚を `viz/reference.png` に差し替える**（同梱サンプルは design vocabulary —
  白地・角丸カード・2 段組の比較・ラインアイコン・強調 1 色 — を示す手本）。
- `reference.png` と配色が未設定のまま生成へ進まない。

## 1. デッキ全体を outline.md 冒頭に書く

- **audience（想定読者）** — 誰が読むか。文体と専門用語の扱いを決める土台。
- **house-style（文体）** — 敬体/常体の別、禁止する語調（煽り・口語・比喩）、
  **専門用語・略語の平易な言い換え表**。図に出してよい語はここで決める。

## 2. 1 枚ずつ骨子を書く

画像 1 枚 = 骨子 1 エントリ。`outline.md` の各スライド節に、intake で集めた内容を落とす。

| 要素 | 中身 |
|---|---|
| `label` | 上に小さく添えるキッカー（一語） |
| `headline` | その 1 枚の結論。**完全な文**。最も大きく見せる。並べると 1 つの説明の流れになる |
| `key` | この 1 枚で理解してほしい**ただ 1 点** |
| `structure` | 希望する図の構造（例: 比較と集約、対立の綱引き、時間軸、階段） |
| `emphasis` | 視覚的に特に強調したいこと |
| `material` | 図に符号化する素材。**カードに載る短句**（見出し＋要点 2〜4） |
| `facts` | 必ず正確に載せる数値。ここにあるものは一字も変えない |

## 3. 素材の書き方（ここが効く）

- **短句で書く。** 長い文を渡すと、Codex は狭いボックスに流し込んで改行を壊す。
  「実在する一人の記録を、そのまま出力に入れません」より「実在する記録は出力に入れません」。
- **専門用語は house-style の言い換えに置き換えてから素材に書く。** 図に出す語は素材の語がそのまま出る。
- **数値は `facts` に集約する。** 素材から数値を消したら `facts` からも消す。載らない数値を要求すると迷う。
- **1 カードに要点 3〜4 項目**を目安に。1〜2 項目しかない素材は、他と統合するか分割して増やす。

## 4. 次へ

`outline.md` が固まったら **`/codex-imagegen:prompt-build`** で生成用プロンプト（`prompts/*.md`）へ変換する。
`outline.md` が正本なので、後で文言を変えるときもここを直して prompt-build を回し直す。

## 注意

- **骨子にレイアウト・配色を書かない。** それは STYLE.md と Codex の仕事。骨子は「内容」に徹する。
- **図の構造（structure）と強調（emphasis）は「方針」で書く。** 具体的な px やカード位置まで指定しない
  （後で個別指摘として generate-review で足すほうが速い）。
- **足りない必須情報を推測で埋めない。** 聞く。埋めた内容はユーザーの言葉に基づくものだけにする。
