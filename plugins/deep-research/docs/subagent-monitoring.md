# サブエージェント監視の規約（subagent-monitoring）

サブエージェントに作業を委譲するスキル（PM / オーケストレータ）が共通で従う規約。

## なぜ要るか

完了報告を待つだけの PM は、**「生きているが進んでいない」状態を検知できない**。
実測例: 委譲先が成果物を書き終えたのにプロセスが終了せず、PM が **15 時間**待ち続けた。
CPU も使わず、エラーも出ないので、人が気づくまで誰も止められなかった。

止まったことより、**止まったと分からないこと**が問題になる。

## 1. 背景起動する（ブロッキングで待たない）

同期実行で待つと、待っている間の状態が見えない。**非同期に起動して、PM は監視側に回る。**

- Claude Code: `Agent` ツールに `run_in_background: true` を指定する。
- 他環境: 同等の非同期委譲機構に読み替える。無ければ §3 のハートビートだけで運用する。

## 2. 一定間隔で状態を見る（ポーリング）

毎回、次の 3 点を見る。**1 つでも動いていれば「進んでいる」と判定する。**

| 見るもの | 何で見るか |
|---|---|
| タスクの状態 | 実行中 / 完了 / 失敗（Claude Code なら `TaskOutput` を `block: false` で） |
| 成果物の更新 | 担当ステップの出力ファイルの更新時刻 |
| 進捗ファイル | `work/progress.json`（§3） |

**間隔の目安**: そのステップの想定所要時間の 1/4。最短 60 秒、最長 10 分。
想定所要が分からないときは 5 分。

## 3. サブエージェント側はハートビートを書く

委譲プロンプトに、次を必ず含める。

> 作業中は `work/progress.json` を更新し続けること。大きな作業単位ごと、
> 少なくとも 5 分に 1 回は `updated_at` を更新する。

```json
{
  "step": "generate",
  "phase": "generator.py の列生成を実装中",
  "updated_at": "2026-08-09T14:20:00+09:00",
  "artifacts": ["src/generator.py"]
}
```

これがあると、PM は**ツール名に依存せず**「進んでいるか」を判定できる。
非同期委譲機構が無い環境では、この規約だけで §2 が成立する。

## 4. 停滞の判定と打ち切り

**停滞** とは、次を全て満たす状態をいう。

- タスクが実行中のまま終わっていない
- `work/progress.json` の `updated_at` が **15 分**以上更新されていない
- 担当ステップの成果物にも更新が無い

検知したら、この順で処理する。

1. **途中成果物を退避する。** `work/stalled-<step>-<YYYYMMDD-HHMM>/` へコピーする。
   打ち切りで失われるものを先に確保する。**この退避を省略しない。**
2. サブエージェントを停止する（Claude Code なら `TaskStop`）。
3. **同じステップを 1 回だけ再起動する。** 再起動時のプロンプトには、停滞した時点の
   `phase` と退避先のパスを伝え、途中から再開できるようにする。
4. **2 回目も停滞したら、再起動しない。** 停止して、経過時間・最後の `phase`・退避先を
   報告する。

自動での打ち切り再実行は **1 ステップにつき 1 回まで**。ループさせない。

## 5. 報告は状態が変わったときだけ

ポーリングのたびに出力しない。次の場合にだけ 1 行出す。

- 状態が変わったとき（開始・完了・失敗）
- 停滞を検知したとき（経過時間と最後の `phase` を添える）
- 打ち切って再起動したとき（退避先を添える）

```
[generate] 停滞を検知: 18 分更新なし（最後の phase: generator.py の列生成を実装中）
[generate] 退避 work/stalled-generate-20260809-1442/ → 停止 → 再起動（1 回目）
```

## 環境ごとの読み替え

固有のツール名はあくまで例示。環境に合わせて読み替える。

| 役割 | Claude Code の例 |
|---|---|
| 非同期に委譲する | `Agent` ツール + `run_in_background: true` |
| 状態を見る | `TaskOutput`（`block: false`） |
| 止める | `TaskStop` |

非同期委譲も状態取得も無い環境では、**§3 のハートビートと成果物の更新時刻だけ**で
§4 の判定を行う。
